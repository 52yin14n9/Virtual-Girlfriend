# 功能验证清单（Lv26 → Lv33）

用途：升级后逐项确认 16 个功能真的生效。也是以后每次回归的依据。

用法：**先正常运行一天**（聊几句、让它发几条主动消息），再执行：

```text
/doctor      # 一眼看出哪些没生效
/status      # 当前各项状态
```

---

## 一、Lv27 长期任务承诺

| 项 | 怎么验证 | 通过判据 |
|---|---|---|
| 澄清问答 | 说「我以后每周的周末打算完成创新创业基础的视频学习」 | 先反问开始时间/钟点/周数，且**不建计划** |
| 补齐后排期 | 依次回答 | 确认一次后 `data/scheduler/scheduled_plans.json` 出现 `metadata.kind=commitment_occurrence` 的计划 |
| 承诺存储 | — | `data/scheduler/commitments.json` 存在且非空 |
| 周期提醒 | 等到到期时间 | 消息带「第 N/M 周」 |

## 八、历史数据清理（Lv33 附带工具）

如果这份数据是从很早的版本一路带过来的，里面可能混着结构性噪声
（空 RAG 记录、同日重复日总结、`user` 为空的对话轮、过期未发的提醒）。

```powershell
python tools\clean_history.py            # 只预览，不改文件（默认）
python tools\clean_history.py --apply    # 执行（自动先备份到 bak\data-backup-*.zip）
```

| 项 | 怎么验证 | 通过判据 |
|---|---|---|
| 预览安全 | 不带 `--apply` 跑一次 | 输出"这是预览"，且 data/ 文件未变 |
| 有备份 | 带 `--apply` 跑 | `bak\data-backup-<时间>.zip` 出现 |
| RAG 去噪 | 清理后再看 | 空文本 0 条、同一天只有 1 条 |
| 幂等 | 再跑一次 `--apply` | 报告"没有需要清理的内容" |
| 档案与生活不受影响 | 清理前后对比 | `user_profile.json` 与 `life.events` 一字未动 |

## 常见"没生效"的原因对照

| 现象 | 最可能的原因 |
|---|---|
| 语料化一直是 `template` | 没配 API Key，或 `SILVERWOLF_PROACTIVE_SPEECH_ENABLED=false` |
| 反思一直 0 次 | 没到周日 21 点、本周重要度没到阈值；用 `/reflect` 手动触发 |
| RAG 全都没有 importance | 那些是 Lv28 之前的旧数据；新写入的才带 |
| 承诺/候选文件不存在 | 对应的对话还没发生过（不是坏了） |
| `/doctor` 说数据是旧的 | 最后活动时间太早，说明最近没真实使用 |
